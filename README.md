# AtariCode800

VSCode extension supporting AtariBASIC syntax coloring, tokenization, and emulation.

A development environment for **Atari 400/800** work: Atari BASIC, 6502
assembly, and C — with a BASIC tokenizer validated byte-for-byte against the
real Atari BASIC ROM.

## Features

- **Atari BASIC tokenizer** — converts a listing to a `.BAS` memory image the
  same way the ROM does, byte for byte, checked against reference files
  generated by `atari800` running the genuine ROM.
- **BASIC Inspector** — a WebView showing the listing (full and abbreviated),
  the tokenized bytes in hex, and the variable tables (VNT / VVT).
- **Syntax highlighting** — Atari BASIC, 6502 assembly (ca65), and ld65 linker
  configs, ported from the Sublime Text grammars.
- **Themes** — `atari800-light` and `atari800-dark`, matching the Sublime
  color schemes.
- **ATASCII support** — a clickable character palette, inverse-video toggling,
  and Unicode ⇄ ATASCII conversion with `$9B` line terminators.
- **Build & run** — assemble with `ca65`/`ld65`, then launch in `atari800`.

## Requirements

| Tool | Purpose | Notes |
|---|---|---|
| `python3` | runs the bundled tokenizer | 3.8+ |
| `atari800` | runs programs | optional |
| `ca65`, `ld65` | 6502 assembly | from cc65; optional |

Set `ataritools.pythonPath` if `python3` is not on your `PATH`.

## File extensions

| Extension | Meaning |
|---|---|
| `.LST` | Atari BASIC listing in **ATASCII** (`$9B` terminators) |
| `.ULST` | Atari BASIC listing in **Unicode/UTF-8**, for authoring |
| `.BAS` | tokenized Atari BASIC memory image |
| `.s`, `.asm` | 6502 assembly |

A `.ULST` is converted to ATASCII on the way to the emulator. Host-only
comments (lines starting with `;`, `#`, or a legacy `.`) are stripped during
that conversion.

## Development

```sh
npm install
npm test            # smoke suite + grammar tokenization
npm run smoke       # behavioural checks only
npm run package     # build a .vsix (requires vsce)
```

### The vendored tokenizer

`python/` holds a **real copy** of the Python tokenizer, not a symlink: a
`.vsix` cannot contain a link that escapes the extension root. Its canonical
home is the Sublime plugin in the [`6502-Tools`][tools] repo, where the corpus
gate and the ROM-reference harnesses live.

```sh
npm run sync:check  # report drift against the canonical copy
npm run sync        # copy it in and verify it runs standalone
```

Only the seven files the tokenizer actually imports are vendored; the
development scripts around it stay in `6502-Tools`.

[tools]: https://github.com/thinkyhead/6502-Tools
